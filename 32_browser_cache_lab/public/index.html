    怎么把实验结果和概念对应起来？
    1. 先判断有没有可用的本地响应。第一次没有，就正常下载，通常得到 200。
    2. 再看是否可以直接复用。max-age 或 Expires 允许且仍新鲜时，可以命中强缓存，无须询问服务端。
    3. 需要验证时发送条件请求。ETag → If-None-Match；Last-Modified → If-Modified-Since。没变返回 304，不传响应体；变了返回 200 和新内容。

    别被 200 迷惑：fetch 通常把“服务端 304 + 本地缓存体”合并成可用响应，JavaScript 读到的 status 仍是 200。Network 面板和右侧服务端记录才能说明线上发生了什么。

    这里验证的是浏览器的 HTTP 缓存。没有 Service Worker、Cache API、localStorage 内容缓存，也没有代理或 CDN。

    同一轮使用固定 URL。“开始新一轮”会换一个 URL，不会清理整个浏览器的缓存。服务重启后请开始新一轮。
